Living handoff doc. Read this first when resuming work (e.g. from another

## What this project is

A **local-only Flask dashboard** (runs on `127.0.0.1:5000`) that is Coach Abood's
single control panel. It reads/writes each client's Google Sheet and a master
sheet (Payments + `⚙` admin tabs), and keeps a local SQLite **workout library**.
Target user is a **non-coder on Windows**; this repo is the handoff package.

Repo: https://github.com/ceasarattar/coach-abood-client-tracker (default branch `main`).

## ✅ Done

- **Workout library seeded** from `seed/programs.json` — 3 programs (PPL UL,
  Upper Lower, Full Body) parsed from the coach's PDF. Loaded by
  `scripts/seed_library.py` (idempotent). Editable in the Library UI.
- **Dynamic workout types** — schedule/exercise "type" are free-text + datalist
  suggestions (so "Upper A", "Conditioning", anything works), not a fixed list.
- **Add existing client** — `/clients/add` registers a sheet you already have.
- **One-click client generation** — the New-Client wizard fills the master `⚙`
  tabs, calls the Apps Script Web App (`apps_script/Code.gs` v7), gets the new
  sheet URL back, and auto-registers the client. Falls back to the manual
  "Coach Tools → Generate Client Template" flow when the web app isn't set up.
  Fixed a real bug: wizard wrote Targets to B3:B7 but the generator reads B2:B6.
- **Cronometer sync foundation** — encrypted per-client credential store
  (`secrets_store.py`, AES/Fernet, gitignored files), CSV fetch via Playwright
  (`cronometer_client.py`; the **CSV parser is unit-tested**, browser steps need
  one real-account validation), sheet-write path (`nutrition_sync.py`, writes
  calories to `Weight!J` by date), and a per-client Cronometer page + Sync button.
- **GitHub packaging** — clean repo layout, secrets gitignored (verified none on
  remote), Windows one-command `setup.bat`, single-instance `run.py` launcher,
  Desktop-shortcut installer (`windows/`), and a non-coder guide
  (`docs/SETUP_WINDOWS.md`).
- **UI cleanup** — removed duplicate Add-Client buttons, dropped the raw Health
  JSON nav link, fixed the floating header button.

## Run it locally (development)

```bash
cd coach_dashboard
./setup.sh                 # mac/linux; Windows: setup.bat
source venv/bin/activate
python run.py              # launcher (single instance, opens browser)
# or: python app.py        # raw dev server
```

**Secrets are NOT in git** — to run, you must have these in `coach_dashboard/`:
- `credentials.json` — Google OAuth Desktop client (from Google Cloud Console).
- `.env` — at least `MASTER_SHEET_ID=...` (copy `.env.example`).
- `token.json` is created on first Google sign-in.
- `clients.yaml` is created as you add clients (or copy `clients.yaml.example`).

Copy those three secret files from the original machine to the new one (they're
gitignored on purpose). Everything else comes from `git clone`.

## UI contract (don't break when restyling)

Routes/templates the redesign must preserve:
- `index.html` uses `cards[]` (each: name, status, latest_weight, weight_delta,
  spark_x/spark_y, last_logged, payment_display, payment_class, plan_usd, error).
- `client.html` uses `d.*` (see `build_detail`) incl. chart arrays
  `weight_30d_*`, `cal_dates/cal_values`, `week_summary`, `payment_*`.
- Forms post to: `/clients/add`, `/clients/new` (actions `write_master` /
  `register`), `/client/<name>/log` (kinds `weight`/`payment`),
  `/client/<name>/cronometer` (actions `save`/`sync`/`delete`),
  `/library/new`, `/library/<id>/edit`, `/library/<id>/delete`.
- Workout-type inputs use `list="wt-list"` + a `<datalist id="wt-list">`.

## Gotchas

- `debug=False` ⇒ Jinja **caches templates**; restart the server to see template
  edits. (`run.py`/`app.py` both run debug off.)
- On this dev mac, system `curl` lived at `/opt/anaconda3/bin/curl`; PDF render
  needed `pymupdf` (poppler wasn't installed).
- Playwright needs `python -m playwright install chromium` (setup does this,
  best-effort; ~150 MB).
